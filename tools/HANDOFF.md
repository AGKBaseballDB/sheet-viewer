# 引き継ぎメモ（どのClaudeアカウント・どのチャットからでも編集するために）

このリポジトリと、パソコンの「AGK男子野球部データ」フォルダ、パスワードがあれば、どのアカウントからでも同じように更新・編集できます。
フォルダが見えないアカウントでも、チャットに貼られたファイルで更新できます（「チャットに貼られたファイルで『更新して』」を読む）。
パスワードはこのリポジトリには書いていません（チャットで別に伝えてもらう）。

## いちばん大事な決まり

1. **作業は必ず `tools/begin.sh` から始める。** GitHubの最新のページとデータベースを取り直します。手元に前回の作業ファイルが残っていても使わない。
2. **2つのアカウント・チャットで同時に作業しない。** 片方が公開したあと、もう片方は `begin.sh` からやり直す。
3. 公開（`tools/deploy.sh`）は、GitHubが作業開始時から変わっていると止まります。止まったら `begin.sh` で取り直し、変更をやり直してから公開する。
4. 個人情報を含むもの（パスワード・secret.json・復号したデータベースやページ）は、リポジトリの外にだけ置く。

## 準備

```
bash tools/begin.sh <作業フォルダ> '<スタッフ用パスワード>' '<選手用パスワード>'
```

ページは2つ：スタッフ用（https://agkbaseballdb.github.io/sheet-viewer/）と選手用（https://agkbaseballdb.github.io/sheet-viewer/player/）。中身は同じで、パスワードだけ別。
公開（deploy.sh / sync.sh）のたびに両方を作り直す。ただし「スタッフ用だけ更新して」と言われたときは STAFF_ONLY=1 を付けて公開し、選手用は前のままにする（次にふつうに更新すると選手用も追いつく）。選手用の鍵は作業フォルダの secret-player.json（begin.sh に選手用パスワードを渡すとできる）。これがないと公開は止まる。

作業フォルダに secret.json（スタッフ用の鍵）・secret-player.json（選手用の鍵）・baseball.sqlite（最新データ）・app.js / app.css（ページのプログラム）ができます。

## 「更新して」（フォルダのファイルを取り込む）

1. パソコンのフォルダを一覧し、Excelが開いている印（`~$` で始まるファイル）がないか確認する。
2. 一覧から listing.json（`[{"path":"トラックマン/xxx.csv","size":…,"mtime":…}]`、パスはフォルダからの相対）を作る。
3. `bash tools/sync.sh plan <secret.json> <listing.json> <作業フォルダ>` → 取り込むファイルが出る。
4. そのファイルを作業フォルダの `inbox/` に同じ相対パスで置く。トラックマン・BlastのCSVは `measure_inbox/トラックマン`・`measure_inbox/Blast` にも置き、測定DBのExcelを `measure.xlsx` として置く。
5. `bash tools/sync.sh apply <secret.json> <listing.json> <作業フォルダ>` → 取り込み・公開・`out/`（取り込み結果.txt・baseball.sqlite.gz・measure.xlsx）。
6. パソコンへ：取り込み結果.txt をフォルダ直下、baseball.sqlite.gz を「データベース」に置き、展開して baseball.sqlite を入れ替える。
   測定DBのExcelは、書き換える前のものを「データベース/バックアップ/…_更新前_日付-時刻.xlsx」に保存してから入れ替える。
7. 取り込みが終わったCSVはフォルダから削除する（エラーになったもの・Excelに書けなかったものは残す）。試合日程.xlsx・トピック.xlsx は削除しない。

## チャットに貼られたファイルで「更新して」（パソコンのフォルダが見えないとき）

パソコンの「AGK男子野球部データ」フォルダにつながっていないアカウント・セッションでは、チャットに貼られたファイルで取り込む。
ページとデータベースはこれで全部更新される（データベースは backup/ に暗号化して入るので、次にだれが begin.sh しても入っている）。
**パソコン側の作業（測定DBのExcel・バックアップ・ファイルの削除・baseball.sqlite の入れ替え）は、フォルダにつながっているアカウントが次の「更新して」でまとめてやる。**
push できるのは、最初から AGKBaseballDB/sheet-viewer を選んで始めたセッションだけ（読むだけのセッションでは公開まで進まない）。

### 1. ファイルの種類を見分ける

置き場所（フォルダ名）で種類が決まるので、貼られたファイルごとに中身を見て、次のどれかに決める。

| 置く場所（パス） | 見分け方 |
|---|---|
| `トラックマン/<元のファイル名>.csv` | TrackManのCSV。見出しに PitchNo・Date・Time・Pitcher・Batter・TaggedPitchType・RelSpeed などが並ぶ。 |
| `Blast/<元のファイル名>.csv` | Blast MotionのCSV（例 All_swings_by_player_….csv）。見出しに Swing Timestamp・Bat Speed (mph)・First_Name・Last_Name・CaptureId など。 |
| `試合記録/<元のファイル名>.csv` または `.xlsx` | 1球1行の試合記録（例 2026年11月07日_獨協大学+vs+エイジェック.csv）。見出しに 日付・球場・イニング・投手名・打者名・球種・球速・投球結果・打席結果・タイムスタンプ など。 |
| `体組成/<元のファイル名>.xlsx` | InBodyの結果。見出しが「1. Name」「14. Test Date / Time」「15. Weight」…（本体から書き出したまま）か、選手名・身長・体重・体脂肪率…。 |
| `体組成/<名前>_<測定日>.pdf` | InBodyのレポートPDF。名前は `Romaji_Name_YYYYMMDD.pdf`（例 Akiyama_Kanta_20260317.pdf）か `漢字_YYYYMMDD.pdf`。違う名前なら、だれのいつのものか聞いてからこの形に直す。 |
| `試合日程.xlsx`（フォルダ直下） | ファイル名がちょうどこれ。下の注意を読む。 |
| `トピック.xlsx`（フォルダ直下） | ファイル名がちょうどこれ。下の注意を読む。 |

- **どれか決められないとき・中身が見出しと合わないときは、推測で取り込まずに聞く。**
- ファイル名は受け取ったものをそのまま使う（同じファイルがあとでパソコンのフォルダに置かれたとき、同じものと分かって二重に入らない）。
- 試合日程.xlsx・トピック.xlsx は、取り込むたびに中身を**全部入れ替える**。貼られたものが最新の全体か（一部だけ・古い版でないか）を確かめてから取り込む。中身を変えたら、そのファイルをパソコン側の人に渡して、フォルダの同じ名前のファイルと入れ替えてもらう（入れ替えないと、次にパソコン側で取り込んだとき古い中身に戻る）。

### 2. listing.json を作って取り込む

1. `begin.sh` のあと、作業フォルダに `inbox/` を作り、上の表のパスでファイルを置く（例 `inbox/トラックマン/20261111-….csv`）。
2. listing.json を作る：`[{"path":"トラックマン/20261111-….csv","size":<バイト数>,"mtime":"<時刻>"}]`。
   - size は受け取ったファイルのバイト数。
   - mtime はファイルの更新時刻が分かればそれ、分からなければ受け取った時刻を UTC の ISO 形式（例 `2026-11-11T06:30:00Z`）で入れる。ずれても問題ない（同じ中身のファイルは、時刻が違っても「変わっていない」と判断される）。
3. `bash tools/sync.sh plan <secret.json> <listing.json> <作業フォルダ>` → 取り込む予定のファイルが出る。ここで一覧を伝え、確認が必要なら止まる。
4. `bash tools/sync.sh apply <secret.json> <listing.json> <作業フォルダ>` → 取り込み・公開。**measure.xlsx は置かない**（このアカウントには測定DBのExcelがない）。
   選手名の対応表（測定DBの選手マスタから作る分）は、データベースに保存されたもの（settings の tm_names_extra）が自動で使われる。
5. `out/取り込み結果.txt` の中身をチャットでそのまま伝える。「選手が分からない」「一致しない」などが出たら、推測で直さずに聞く。

### 3. 結果の戻し方・パソコン側でやること

- 取り込み結果.txt：チャットで中身を伝える（パソコンに置く必要はない。次にパソコン側で取り込むと新しい取り込み結果.txt に置き換わる）。
- baseball.sqlite.gz：**送らない**（個人情報を含むため）。最新のデータベースは backup/ に暗号化して入っていて、パソコン側の次の「更新して」でフォルダの baseball.sqlite も新しくなる。
- 測定DBのExcel：このアカウントでは触らない。使ったトラックマン・BlastのCSVを、パソコン側の人に**同じファイル名のまま**渡してもらう（LINEなどでよい）。パソコン側では、それを「トラックマン」「Blast」フォルダに入れて「更新して」。データベースにはもう入っているので二重にはならず、測定DBのExcel（と選手マスタの行）にだけ足される。そのあとCSVはいつもどおり削除される。
- 体組成のExcel・PDF、試合記録：パソコン側に渡さなくてよい（データベースに入っているため）。原本を残したいときだけフォルダに入れる（入れても二重にはならない）。
- バックアップ・削除・baseball.sqlite の入れ替えは、パソコン側（フォルダにつながっているアカウント）だけがやる。

### 4. 同時に作業しない

- 作業を始める前に、もう一方の人へ「今から更新します」と連絡する（LINEなど）。終わったら「終わりました」と、`begin.sh` や公開で出たコミットの番号（7文字）を伝える。
- `begin.sh` の最後に出る「公開中のコミット」が、もう一方から聞いた番号と同じか確かめてから作業する。
- 公開が「GitHubの内容が作業を始めたときから変わっています」で止まったら、もう一方が先に公開している。`begin.sh` からやり直す（同じファイルで取り込み直してよい）。

## ページ（見た目・機能）を変えるとき

1. `begin.sh` のあと、作業フォルダの app.js / app.css を編集する。
2. `node --no-warnings tools/bbdb.cjs set-app --db <作業>/baseball.sqlite --js <作業>/app.js --css <作業>/app.css`
3. `node --no-warnings tools/bbdb.cjs export --db <作業>/baseball.sqlite --out <作業>/page.html` → ブラウザで確認。
4. `BACKUP_DB=<作業>/baseball.sqlite PLAYER_SECRET=<作業>/secret-player.json bash tools/deploy.sh <作業>/page.html <作業>/secret.json <版の名前>`
5. パソコンの「データベース」の baseball.sqlite も新しいものに入れ替える。

## これまでに決めたこと

- 返事は日本語。
- 規定（打席＝チーム試合数×2、投球回＝チーム試合数×1）は、ホームのランキングだけに使う。成績表は全員を同じ扱いで表示。
- 退部者＝分析シートの選手一覧で非表示にしている選手。ホームの選手カード・注目選手からも外す（記録がまだない選手は表示）。
- 試合の種類（OP戦・公式戦・JABA大会など）は、試合日程.xlsx の「大会」欄 → なければ日付と球場の大会日程から自動判定 → それ以外はOP戦。
- 試合日程.xlsx：フォルダ直下に置いたまま。「メモ」の列はページに出さない。BC映像の列も使う。映像は「中継映像」「CC映像」の列（列の見出しが映像の名前になる）。
- トピック.xlsx：フォルダ直下に置いたまま。列は 日付・区分・タイトル・本文・リンク・出典・画像・注目。取り込むたびに全部入れ替え。ページの TOPICS タブ（一番右）とホームのトピック欄に新しい順で出る（注目に○があるものがホームの大きな枠）。出どころ（公式・ニュース・SNS・部内限定）はURLか出典列から自動判定。区分か出典に「部内」で部内限定の印。
- Blastは、トラックマンの投球と時刻が合ったスイングだけをデータベースと測定DBのExcelに入れる。トラックマンがない試合（In Game）は、試合記録のタイムスタンプ（記録係の入力は打った2〜4秒後）で、自チームの打者が振った投球（空振り・ファウル・打球）に結びつける（Blastの時刻はUTCなので+9時間）。
- 体組成：InBody本体から書き出したままのExcel（見出しが「1. Name」「15. Weight」…、行ごとに「14. Test Date / Time」）は、月ごとの記録（例 2026-11）にまとめ、同じ月の記録に選手ごとに足す（チームは月に1回測る。日付は気にしない）。同じ月に同じ選手を2回以上測っていたら、その月の最初の測定を使う。取り込んだら体組成フォルダから削除。
- 取り込みでエラーになったファイルは、次の「更新して」でもう一度試す。
- パソコンへ書き戻すファイルは、毎回ちがう名前で outputs に置いてから送る（同じ名前だと前の中身が書かれることがあった）。
- 体組成のレポートPDF（例 Akiyama_Kanta_20260317.pdf ＝ 名前のローマ字_測定日）：体組成フォルダに入れて「更新して」。名前は選手マスタのﾌﾘｶﾞﾅをローマ字にした表（DB の roman_names。測定DBのExcelを置いて取り込むと作り直す）で選手に結びつける。漢字の名前_日付.pdf でもよい。
  PDFはDB（body_docs）に入り、公開時に docs/<id>.enc（ページ画像）と docs/<id>.pdf.enc（PDF）として暗号化して置く（deploy.sh が BACKUP_DB から作る）。暗号の鍵は文書用の鍵（DBの meta doc_key）で、スタッフ用・選手用どちらのページにも暗号の中に入っている（選手用は ../docs/ を読む）。右側の画面（Claudeのアーティファクト）に出すときは docs/ のファイルも一緒に公開する。取り込んだPDFはフォルダから削除。
- 測定DBのExcelの「選手マスタ」は、選手ごと・測定日ごとに1行。トラックマンを取り込むと、その日の投手・打者でまだ行がない選手の行を、その選手の最新の行（A〜W列）を写して自動で足す（メモ＝場所は、同じ機械・同じ練習の種類で多く書かれている場所。投球＝さくら球場、打撃＝ラボが多い）。前の行がない選手（相手の投手など）は作らない。手で足すときは `--master-dates 2026-11-04` を付けて measure_xlsx.py を動かす。
- 試合記録の相手チームが「対戦チーム」になっていて、相手が分かるとき（試合日程や本人の連絡）は `node tools/bbdb.cjs rename-team --db <作業>/baseball.sqlite --file <file_id> --from 対戦チーム --to <相手名>` で直してから公開する。2026-11-14 の試合は「白鷗大学」に直した。
- 試合映像（打球ごとの短い映像・2026-11-12 デモ）：野手の分析シートの打球方向で、映像のある打球に金色の丸が付き、押すとその打球の映像（投球の約7秒前から17秒）が開く。シートの上にも映像の一覧が出る。
  映像は clips/<id>.mp4.enc（文書用の鍵で暗号化。IV 12バイト＋暗号文＋タグ）としてリポジトリに置いたまま、公開のたびに引き継ぐ。一覧はDBの video_clips（タイムスタンプで投球の行に結びつく）。
  作り方：中継の録画から ffmpeg で切り出す（-ss <開始秒> -t 17 -vf scale=960:-2 -c:v libx264 -preset veryfast -crf 27 -c:a aac -b:a 96k -movflags +faststart）→ `node tools/bbdb.cjs add-clips --db <作業>/baseball.sqlite --list <list.json> --out <リポジトリ>/clips`（list.json は [{file,ts,date,batter,inning,result,opponent,source,start,dur}]）。
  YouTubeの方法（容量を使わない）：list.json に file の代わりに yt（動画ID）と start（再生を始める秒＝打球の約7秒前）を書いて同じ add-clips。押すとその秒から中継のYouTubeを再生する（埋め込み＋「YouTubeで開く」）。8/31 沖縄電力戦：動画 Mmv3HPQnATM、映像の秒 ＝ 記録の時刻 − 19:12:23（開始は7秒前）。
  2026-11-12：試合日程.xlsx にYouTubeがある10試合すべてを、両チームの打球（打球方向のある投球）で入れた。開始の秒 ＝ 記録の時刻 − 最初の投球の記録時刻 ＋ ずれ − 7。ずれ（秒）：8/4 6.0→7.6（始め→終わりで直線）、8/8 36.2→36.6、8/11 110.8→110.4、8/13 162.9→162.7、8/16 131.5→131.2、8/27 112.0→111.8、9/13 155.6→155.3、10/31 CC 34、11/7 BC 100・CC 5.5（11/7 は BC と CC を切り替えられる）。8/31 は中継（記録の時刻 − 19:12:23）。9/5 は映像ファイル（両チーム）。
  2026-11-12〜13 追加（ずれは一定）：3/2 185.5、3/7 BC 74.5・CC 227、3/8 182.5、3/9 133、3/12 130.5、3/16 309.5、3/17 BC 168.5・CC 169、3/20 157.5、3/22 179、5/30 BC 174・BC_下 175、6/4 BC 139・BC_下 109、6/5 BC・BC_下 33.5（タイトルどおり btCAvnhncVo が BC、kmUZE8EpCWM が BC_下）、6/8 143、6/9 155、6/10 BC_下 120（記録の500秒の中断より前だけ。中断後は映像が約30分止まっていて未対応）、6/14 166、6/19 101、6/26 127、9/19 19.5、9/22 215、9/24 169.5、9/25 197.5。

- パスワードを入れる最初の画面には、チーム名やロゴを出さない（誰でも見られる画面のため）。
